## 一、为什么需要访问控制

L01 的示例里，成员变量全部写成 `public`，任何人都能直接修改：

```cpp
BankAccount acc;
acc.balance = -99999;   // 合法！但这显然不合理
```

这就是没有访问控制的问题——**类的内部状态完全暴露在外，任何代码都能随意破坏它的合法性**。

访问控制（access control）是封装的语法支撑。它让你划定一条边界：

- 哪些东西是类的**公开接口**，外部可以用
- 哪些东西是类的**内部实现**，只有类自己能碰

```
┌─────────────────────────────┐
│          BankAccount        │
│  ┌───────────────────────┐  │
│  │  private              │  │
│  │  double balance       │  │  ← 外部看不见，摸不到
│  └───────────────────────┘  │
│                             │
│  public                     │
│  void deposit(double)       │  ← 外部通过这里操作
│  void withdraw(double)      │
│  double getBalance()        │
└─────────────────────────────┘
```

## 二、三种访问权限

### 2.1 `public`

任何地方都可以访问。类的对外接口应当是 `public`。

```cpp
class Circle {
public:
    double radius;          // 外部可读写
    double area();          // 外部可调用
};
```

### 2.2 `private`

只有**类自身的成员函数**（以及 `friend`，后面讲）可以访问。外部代码一律无法触碰。

```cpp
class Circle {
private:
    double radius;          // 外部无法直接访问

public:
    void setRadius(double r);
    double getRadius();
    double area();
};
```

### 2.3 `protected`

介于 `public` 和 `private` 之间。外部代码无法访问，但**派生类（子类）**可以访问。

`protected` 的设计意图是为继承服务的。在没有继承关系的场景下，它和 `private` 行为一致。

```cpp
class Animal {
protected:
    std::string name;   // 子类可以访问，外部不能
public:
    Animal(std::string n) : name(n) {}
};

class Dog : public Animal {
public:
    void bark() {
        // 可以访问 name，因为 Dog 是 Animal 的子类
        std::cout << name << " says: Woof!" << std::endl;
    }
};
```

> `protected` 和继承的关系将在模块二详细展开，本课了解概念即可。

### 访问权限速查表

| 访问位置 | `public` | `protected` | `private` |
|---|---|---|---|
| 类自身的成员函数 | ✓ | ✓ | ✓ |
| 派生类的成员函数 | ✓ | ✓ | ✗ |
| 类外部的代码 | ✓ | ✗ | ✗ |
| `friend` 函数/类 | ✓ | ✓ | ✓ |

## 三、封装原则（重点）

封装不只是"把变量改成 `private`"，它背后有一套设计思想：

**类对外暴露"能做什么"，而不是"怎么存的"。**

### 3.1 数据隐藏的真正价值

考虑一个表示角度的类，内部用弧度存储：

```cpp
class Angle {
private:
    double radians;   // 内部用弧度

public:
    void setDegrees(double deg) {
        radians = deg * 3.14159 / 180.0;
    }
    double getDegrees() const {
        return radians * 180.0 / 3.14159;
    }
    double getRadians() const {
        return radians;
    }
};
```

外部代码完全不知道（也不关心）内部是用弧度存的。有一天你决定改成用角度存，只需要改类内部的实现——所有调用这个类的代码**一行都不用改**。

这就是封装的核心价值：**隔离变化**。

### 3.2 通过接口保证合法性

```cpp
class Age {
private:
    int value;

public:
    void set(int v) {
        if (v < 0 || v > 150) {
            std::cout << "非法年龄值" << std::endl;
            return;
        }
        value = v;
    }

    int get() const {
        return value;
    }
};
```

如果 `value` 是 `public`，任何代码都可以写 `age.value = -5`，类根本无力阻止。把它改成 `private` 并通过 `set()` 控制写入，类就能保证自己的状态永远合法。

**封装 = 数据隐藏 + 状态保护**。

## 四、Getter 与 Setter（详解）

Getter 是只读接口，Setter 是带验证的写入接口。这是实现封装最常见的手段。

### 4.1 基本写法

```cpp
class Person {
private:
    std::string name;
    int age = 0;

public:
    // Getter：只读，声明为 const（不修改对象状态）
    std::string getName() const { return name; }
    int getAge() const { return age; }

    // Setter：写入，可以加验证逻辑
    void setName(const std::string& n) {
        if (n.empty()) {
            std::cout << "姓名不能为空" << std::endl;
            return;
        }
        name = n;
    }

    void setAge(int a) {
        if (a < 0 || a > 150) {
            std::cout << "年龄不合法" << std::endl;
            return;
        }
        age = a;
    }
};
```

### 4.2 不是每个成员变量都需要 Getter/Setter

这是初学者最常见的误区：看到 `private` 就条件反射地给每个变量配一套 getter/setter，结果等于白写了 `private`——数据又全暴露出去了。

判断标准：

| 情形 | 建议 |
|---|---|
| 变量是外部需要读取的 | 提供 getter |
| 变量是外部需要修改的，且需要验证 | 提供 setter |
| 变量完全是内部实现细节，外部不关心 | 既不提供 getter 也不提供 setter |
| 变量只读，构造后不变 | 只提供 getter，不提供 setter |

```cpp
class Circle {
private:
    double radius;
    double cachedArea;   // 内部缓存，外部不需要知道这个变量的存在

public:
    Circle(double r) : radius(r), cachedArea(r * r * 3.14159) {}

    double getRadius() const { return radius; }   // 外部可读 radius
    double area() const { return cachedArea; }    // 外部用 area()，不关心怎么存的

    // 没有 setCachedArea——这是内部实现，不对外暴露
};
```

### 4.3 返回引用的 Getter（进阶，了解即可）

有时 getter 返回引用而非副本，以避免拷贝开销（对大型对象有意义）。但返回 `const` 引用，不能被修改：

```cpp
class Library {
private:
    std::string longDescription;

public:
    // 返回 const 引用，外部只能读，不能改
    const std::string& getDescription() const {
        return longDescription;
    }
};
```

> ⚠️ 不要返回 `private` 成员的**非 `const` 引用**，那等于把 `private` 的保护完全绕开了。

## 五、`friend`：打破封装的受控通道

`friend` 声明允许指定的外部函数或类访问本类的 `private` 和 `protected` 成员。

### 5.1 友元函数

```cpp
class Vector2D {
private:
    double x, y;

public:
    Vector2D(double x, double y) : x(x), y(y) {}

    // 声明 dot 是友元函数，它可以访问 private 成员
    friend double dot(const Vector2D& a, const Vector2D& b);
};

// 这是一个普通函数（不是成员函数），但可以访问 private 成员 x, y
double dot(const Vector2D& a, const Vector2D& b) {
    return a.x * b.x + a.y * b.y;
}
```

`friend` 声明写在类内部（位置在 `public`/`private` 区域都无所谓，效果相同），但 `dot` 本身不是类的成员函数。

### 5.2 友元类

如果整个类 B 都需要访问类 A 的私有成员，可以把 B 声明为 A 的友元类：

```cpp
class Engine;  // 前向声明

class Car {
private:
    int horsepower = 200;

    friend class Engine;   // Engine 可以访问 Car 的所有私有成员
};

class Engine {
public:
    void tune(Car& car) {
        car.horsepower += 50;   // 合法，因为 Engine 是 Car 的友元
        std::cout << "调校后马力：" << car.horsepower << std::endl;
    }
};
```

### 5.3 友元操作符重载（常用场景）

`friend` 最常见的实际用途是重载 `<<` 输出运算符，因为 `<<` 的左侧是 `std::ostream`，无法写成成员函数：

```cpp
class Point {
private:
    double x, y;

public:
    Point(double x, double y) : x(x), y(y) {}

    friend std::ostream& operator<<(std::ostream& os, const Point& p);
};

std::ostream& operator<<(std::ostream& os, const Point& p) {
    os << "(" << p.x << ", " << p.y << ")";
    return os;
}

// 使用
Point p(3.0, 4.0);
std::cout << p << std::endl;  // 输出：(3, 4)
```

### 5.4 ⚠️ `friend` 的使用边界（重点注意）

`friend` **单向且不传递**：

```cpp
// A 把 B 声明为友元，B 可以访问 A 的私有成员
// 但 A 不能访问 B 的私有成员——友元不是互相的
class A {
    friend class B;
private:
    int secret = 42;
};

class B {
private:
    int data = 0;
public:
    void readA(A& a) { a.secret; }  // ✓ B 是 A 的友元
};

class C : public B {
public:
    void tryReadA(A& a) { a.secret; }  // ✗ 友元不继承，C 不是 A 的友元
};
```

**什么时候该用 `friend`：**

- 运算符重载（尤其是 `<<`、`>>`）需要访问私有数据，而又无法写成成员函数时
- 两个紧密协作的类，关系明确、边界清晰（比如迭代器和容器）

**什么时候不该用 `friend`：**

- 懒得写 getter/setter，直接用 `friend` 绕过——这破坏了封装，是设计退步
- 大范围地把外部函数都声明为友元，说明类的边界划定本身有问题

> **原则：`friend` 是封装边界上的一扇受控小门，不是推倒封装的理由。用得越少越好，用时要有明确原因。**

## 六、访问控制的常见错误汇总

### ❌ 把所有成员变量都写 public

```cpp
// 不好的写法：
class Temperature {
public:
    double celsius;  // 任何人都能写入负绝对零度
};
```

```cpp
// 正确的写法：
class Temperature {
private:
    double celsius;
public:
    void set(double c) {
        if (c < -273.15) { /* 报错 */ return; }
        celsius = c;
    }
    double get() const { return celsius; }
};
```

### ❌ 给每个 private 变量都机械配一个 getter+setter

```cpp
// 伪封装：看起来私有，实际等于公开
class Foo {
private:
    int x;
public:
    int getX() { return x; }
    void setX(int v) { x = v; }   // 没有任何限制，等于 public int x
};
```

问自己：这个变量对外需要读吗？需要写吗？如果都不需要，就不要提供接口。

### ❌ 返回 private 成员的非 const 引用

```cpp
class Wallet {
private:
    double money = 0;
public:
    double& getMoney() { return money; }  // 危险！
};

Wallet w;
w.getMoney() = -500;   // 封装完全失效
```

### ❌ 把 `friend` 当作懒人方案

```cpp
class Config {
    friend class App;   // 因为懒得写 getter，直接把整个 App 变成友元
private:
    std::string dbUrl;
    int port;
    // ...几十个私有字段全暴露给 App 了
};
```

## 七、完整示例：用户账户系统

```cpp
// UserAccount.h
#pragma once
#include <string>

class UserAccount {
private:
    std::string username;
    std::string passwordHash;   // 不对外暴露明文密码
    int loginAttempts = 0;
    bool locked = false;

    std::string hashPassword(const std::string& pwd);  // 内部工具函数，不对外暴露

public:
    UserAccount(const std::string& user, const std::string& pwd);

    std::string getUsername() const;
    bool isLocked() const;

    bool login(const std::string& pwd);
    void resetPassword(const std::string& newPwd);

    friend std::ostream& operator<<(std::ostream& os, const UserAccount& acc);
};
```

```cpp
// UserAccount.cpp
#include "UserAccount.h"
#include <iostream>

// 极简"哈希"：真实项目用 bcrypt 等，这里仅作演示
std::string UserAccount::hashPassword(const std::string& pwd) {
    return "HASH_" + pwd;
}

UserAccount::UserAccount(const std::string& user, const std::string& pwd)
    : username(user), passwordHash(hashPassword(pwd)) {}

std::string UserAccount::getUsername() const { return username; }
bool UserAccount::isLocked() const { return locked; }

bool UserAccount::login(const std::string& pwd) {
    if (locked) {
        std::cout << "账户已锁定" << std::endl;
        return false;
    }
    if (hashPassword(pwd) == passwordHash) {
        loginAttempts = 0;
        std::cout << "登录成功，欢迎 " << username << std::endl;
        return true;
    }
    ++loginAttempts;
    if (loginAttempts >= 3) {
        locked = true;
        std::cout << "密码错误次数过多，账户已锁定" << std::endl;
    } else {
        std::cout << "密码错误，还剩 " << (3 - loginAttempts) << " 次机会" << std::endl;
    }
    return false;
}

void UserAccount::resetPassword(const std::string& newPwd) {
    passwordHash = hashPassword(newPwd);
    loginAttempts = 0;
    locked = false;
    std::cout << "密码已重置" << std::endl;
}

std::ostream& operator<<(std::ostream& os, const UserAccount& acc) {
    os << "用户：" << acc.username
       << "｜状态：" << (acc.locked ? "已锁定" : "正常");
    return os;
}
```

```cpp
// main.cpp
#include "UserAccount.h"
#include <iostream>

int main() {
    UserAccount u("alice", "mypassword");

    u.login("wrongpwd");
    u.login("wrongpwd");
    u.login("wrongpwd");   // 第三次错误，触发锁定
    u.login("mypassword"); // 账户已锁定，无法登录

    u.resetPassword("newpass123");
    u.login("newpass123"); // 登录成功

    std::cout << u << std::endl;

    return 0;
}
```

**输出：**

```
密码错误，还剩 2 次机会
密码错误，还剩 1 次机会
密码错误次数过多，账户已锁定
账户已锁定
密码已重置
登录成功，欢迎 alice
用户：alice｜状态：正常
```

## 八、本课小结

| 概念 | 要点 |
|---|---|
| `public` | 任何地方可访问，类的对外接口 |
| `private` | 仅类自身可访问，保护内部状态 |
| `protected` | 仅类自身和子类可访问，为继承服务 |
| 封装的价值 | 隔离变化、保证状态合法性，而非单纯"藏数据" |
| Getter/Setter | 不是机械配对，按需提供，setter 应含验证逻辑 |
| `friend` | 单向、不传递、不继承，谨慎使用，有明确理由再用 |

### 作业一：体温记录仪（基础）

设计一个 `Thermometer` 类，要求：

- 私有成员变量：当前温度 `temperature`（`double`，单位摄氏度），初始值 `36.5`
- 提供 getter 获取当前温度
- 提供 setter 设置温度，要求：
  - 拒绝低于 `-273.15`（绝对零度）的值
  - 拒绝高于 `100.0` 的值（超出体温计量程）
  - 非法值打印提示信息，不更新温度
- 提供一个 `status()` 函数，根据温度打印状态：
  - 低于 `36.0`：偏低
  - `36.0` ~ `37.3`：正常
  - 高于 `37.3`：发烧
- 在 `main` 中测试合法值、非法值、以及三种状态分支是否都能触发

此作业重点练习 setter 的验证逻辑，以及"不对外暴露的变量只按需提供接口"的习惯。

### 作业二：二维向量库（进阶）

设计一个 `Vec2` 类，表示二维向量，要求：

- 私有成员：`x`、`y`（`double`）
- 提供构造函数 `Vec2(double x, double y)`（暂时用普通赋值实现，L03 会讲初始化列表的标准写法）
- 提供以下成员函数：
  - `double getX() const` / `double getY() const`
  - `double length() const`：返回向量的模长（`sqrt(x*x + y*y)`）
  - `Vec2 add(const Vec2& other) const`：返回两个向量相加的结果（返回一个新的 `Vec2` 对象）
  - `Vec2 scale(double factor) const`：返回向量乘以标量的结果
  - `void normalize()`：将向量归一化（除以自身模长），若模长为 0 则打印警告并不做修改
- 用 **`friend`** 实现 `operator<<`，使 `std::cout << v` 能输出 `(x, y)` 格式
- 在 `main` 中：
  - 创建两个向量，测试加法和缩放
  - 打印归一化前后的向量和模长，验证归一化后模长为 1

此作业重点练习：什么情况下成员函数应当声明为 `const`，以及 `friend` 的合理使用场景（运算符重载）。

### 作业三：迷你权限系统（综合）

设计一个 `Document` 类和一个 `Editor` 类，模拟文档的权限管理，要求：

**`Document` 类：**
- 私有成员：文档内容 `content`（`std::string`）、是否只读 `readOnly`（`bool`，初始 `false`）、作者名 `author`（`std::string`）
- 公开接口：
  - `getContent() const`：获取内容
  - `getAuthor() const`：获取作者名
  - `isReadOnly() const`：返回只读状态
  - `setReadOnly(bool flag)`：设置只读状态
- 把 `Editor` 类声明为 `Document` 的友元

**`Editor` 类：**
- 私有成员：编辑器名称 `name`
- 公开接口：
  - `edit(Document& doc, const std::string& newContent)`：修改文档内容——若文档是只读状态则拒绝并打印提示，否则直接修改 `doc` 的私有 `content`（通过友元权限）
  - `forceEdit(Document& doc, const std::string& newContent)`：强制编辑，无视只读状态，直接修改内容，并打印"[警告] 强制覆盖只读文档"

**在 `main` 中：**
1. 创建一个文档，普通写入一段内容
2. 将文档设为只读，尝试普通编辑（应被拒绝）
3. 用强制编辑修改内容，验证内容确实改变了
4. 用一段普通函数（非友元）尝试直接访问 `Document` 的私有 `content`——这段代码**写出来但注释掉**，观察编译器给出的错误信息，并在注释里写下你看到的错误提示

此作业重点练习：友元的单向性和使用时机，以及理解"封装不是绝对安全锁，而是边界契约"。
