## 一、构造函数是什么

对象被创建的那一刻，C++ 会自动调用一个特殊的函数——**构造函数**。它的职责只有一个：**把对象初始化成一个合法的状态**。

构造函数的语法特征：

- 函数名与类名完全相同
- **没有返回值**（连 `void` 也不写）
- 可以重载（同一个类可以有多个构造函数）

```cpp
class Point {
public:
    double x;
    double y;

    Point() {           // 构造函数：无参数
        x = 0.0;
        y = 0.0;
    }
};

Point p;  // 对象被创建，构造函数自动调用，x=0, y=0
```

构造函数**不能被手动调用**，它由编译器在对象创建时自动触发。

## 二、默认构造函数

### 2.1 什么是默认构造函数

无参数的构造函数（或所有参数都有默认值的构造函数）称为**默认构造函数**。

```cpp
class Dog {
public:
    std::string name;
    int age;

    Dog() {         // 默认构造函数
        name = "Unknown";
        age = 0;
    }
};

Dog d;  // 调用默认构造函数
```

### 2.2 编译器生成的默认构造函数

如果你**没有写任何构造函数**，编译器会自动生成一个默认构造函数——但它什么也不做（不会初始化内置类型成员）。

```cpp
class Foo {
public:
    int x;      // 不会被初始化，值不确定！
    double y;
};

Foo f;
// f.x 和 f.y 的值是未定义的垃圾值
```

如果你**写了任何有参数的构造函数**，编译器就不再自动生成默认构造函数。

```cpp
class Bar {
public:
    int x;
    Bar(int val) { x = val; }   // 写了有参构造
};

Bar b;      // 编译错误：没有默认构造函数
Bar b(10);  // 正确
```

如果你需要两者共存，必须显式补写一个无参构造函数，或者用 `= default` 告诉编译器生成：

```cpp
class Bar {
public:
    int x = 0;
    Bar() = default;            // 显式要求编译器生成默认构造
    Bar(int val) { x = val; }
};

Bar b1;      // 正确，调用默认构造
Bar b2(10);  // 正确
```

## 三、参数构造函数与重载

同一个类可以有多个构造函数，参数列表不同即可，这叫构造函数重载：

```cpp
class Rectangle {
public:
    double width;
    double height;

    Rectangle() {                           // 无参：默认正方形 1x1
        width  = 1.0;
        height = 1.0;
    }

    Rectangle(double side) {                // 一个参数：正方形
        width  = side;
        height = side;
    }

    Rectangle(double w, double h) {         // 两个参数：任意矩形
        width  = w;
        height = h;
    }

    double area() { return width * height; }
};

Rectangle r1;           // 调用无参构造，1x1
Rectangle r2(5.0);      // 调用单参构造，5x5
Rectangle r3(4.0, 6.0); // 调用双参构造，4x6
```

编译器根据你传入的参数数量和类型，自动匹配调用哪个构造函数。

## 四、初始化列表 ⭐（核心难点）

### 4.1 语法

初始化列表写在构造函数参数括号之后、函数体大括号之前，用冒号 `:` 引导：

```cpp
class Point {
public:
    double x;
    double y;

    Point(double px, double py) : x(px), y(py) {
        // 函数体可以为空
    }
};
```

语法结构为：

```
构造函数名(参数列表) : 成员1(初始值1), 成员2(初始值2), ... {
    函数体
}
```

### 4.2 初始化列表 vs 函数体赋值——本质的不同

这是本课最重要的内容，也是最容易被忽略的知识点。

看起来下面两种写法效果相同：

```cpp
// 写法 A：函数体赋值
class Person {
public:
    std::string name;
    int age;

    Person(std::string n, int a) {
        name = n;    // 这是"赋值"，不是"初始化"
        age  = a;
    }
};

// 写法 B：初始化列表
class Person {
public:
    std::string name;
    int age;

    Person(std::string n, int a) : name(n), age(a) {
        // 这是"初始化"
    }
};
```

它们实际上做了不同的事情：

| | 写法 A（函数体赋值） | 写法 B（初始化列表） |
|---|---|---|
| 执行时机 | 先用默认构造创建成员，再赋值 | 直接用指定值构造成员，一步完成 |
| 对 `std::string` | 先调用默认构造，再调用赋值运算符 | 直接调用拷贝构造，只一次 |
| 对内置类型（int, double）| 无区别 | 无区别 |

对于 `std::string` 这样的对象类型成员，写法 A 多做了一次无意义的默认构造，效率更低。

### 4.3 必须使用初始化列表的三种情况

以下三种成员，**只能用初始化列表初始化，在函数体内赋值会导致编译错误**：

**情况一：`const` 成员变量**

`const` 变量只能被初始化一次，不能被赋值：

```cpp
class Config {
public:
    const int MAX_SIZE;

    // 错误写法：
    Config(int n) {
        MAX_SIZE = n;  // 编译错误：const 变量不能赋值
    }

    // 正确写法：
    Config(int n) : MAX_SIZE(n) {}  // 必须用初始化列表
};
```

**情况二：引用类型成员**

引用必须在声明时绑定，且之后不能重新绑定：

```cpp
class Wrapper {
public:
    int& ref;

    // 错误写法：
    Wrapper(int& r) {
        ref = r;  // 编译错误：引用无法被"赋值"重新绑定
    }

    // 正确写法：
    Wrapper(int& r) : ref(r) {}
};
```

**情况三：没有默认构造函数的成员对象**

如果一个类的成员是另一个类的对象，而那个类没有默认构造函数：

```cpp
class Engine {
public:
    int horsepower;
    Engine(int hp) : horsepower(hp) {}   // 只有有参构造，没有默认构造
};

class Car {
public:
    Engine engine;

    // 错误写法：
    Car(int hp) {
        engine = Engine(hp);  // 编译错误：先要创建 engine，但 Engine 没有默认构造
    }

    // 正确写法：
    Car(int hp) : engine(hp) {}  // 直接用 hp 构造 engine
};
```

### 4.4 初始化顺序：按成员声明顺序，不是列表顺序

初始化列表中成员的**初始化顺序**，取决于它们在类中**声明的顺序**，而不是在初始化列表中书写的顺序。

```cpp
class Danger {
public:
    int a;
    int b;

    // 初始化列表中先写 b，后写 a
    // 但实际执行时，先初始化 a（因为 a 先声明），再初始化 b
    Danger(int x) : b(x), a(b * 2) {   // ⚠️ 陷阱！
        // a 先被初始化，但此时 b 还没初始化，b 是垃圾值
        // 所以 a 的值是未定义的！
    }
};
```

**避免这个陷阱的规则：**

> 保持初始化列表中的书写顺序与类中成员声明顺序一致。

```cpp
class Safe {
public:
    int b;   // b 先声明
    int a;   // a 后声明

    Safe(int x) : b(x), a(b * 2) {  // 列表顺序和声明顺序一致，安全
    }
};
```

## 五、`explicit` 关键字

### 5.1 隐式转换的危险

当一个构造函数只有一个参数时，C++ 允许用该类型的值**隐式地**转换成该类的对象：

```cpp
class Meter {
public:
    double value;
    Meter(double v) : value(v) {}
};

void printDistance(Meter m) {
    std::cout << m.value << " m" << std::endl;
}

printDistance(3.5);     // 3.5 被隐式转换为 Meter(3.5)，可以通过编译
```

大多数情况下这是危险的——调用者可能根本不知道发生了隐式转换，导致难以排查的 bug：

```cpp
class Buffer {
public:
    int size;
    Buffer(int n) : size(n) {}
};

void process(Buffer buf) { /* ... */ }

process(42);   // 你是想传一个"42 字节的缓冲区"，还是写错了参数？
               // 编译器不会报错，但逻辑可能是错的
```

### 5.2 用 `explicit` 禁止隐式转换

在构造函数前加 `explicit`，则禁止该构造函数用于隐式转换，只能显式构造：

```cpp
class Buffer {
public:
    int size;
    explicit Buffer(int n) : size(n) {}
};

process(42);              // 编译错误：不允许隐式转换
process(Buffer(42));      // 正确：显式构造
process(static_cast<Buffer>(42));  // 也正确
```

**实践建议：** 对所有单参数构造函数，默认加 `explicit`。只有在你确实希望允许隐式转换时，才去掉它。

## 六、委托构造函数（C++11）

当多个构造函数有重复的初始化逻辑时，可以让一个构造函数调用另一个，避免代码重复：

```cpp
class Date {
public:
    int year;
    int month;
    int day;

    // 主构造函数，负责真正的初始化
    Date(int y, int m, int d) : year(y), month(m), day(d) {
        // 假设这里有复杂的验证逻辑
    }

    // 委托构造：调用上面那个主构造函数
    Date() : Date(2024, 1, 1) {}          // 默认日期
    Date(int y) : Date(y, 1, 1) {}        // 只指定年份
};

Date d1;           // 2024-01-01
Date d2(2025);     // 2025-01-01
Date d3(2025, 6, 15);  // 2025-06-15
```

委托构造函数的限制：**委托构造函数不能再有初始化列表**，因为初始化职责已经移交给被委托的构造函数。

## 七、注意事项汇总

### ⚠️ 不要在构造函数里做可能失败的操作

构造函数没有返回值，无法通过返回值报告错误。以下两种方案常见：

- 把可能失败的操作拆到普通成员函数 `init()` 里，构造函数只做轻量初始化
- C++ 正规做法是在构造函数里抛出异常（涉及异常机制，后续课程再讲）

### ⚠️ 构造函数不是普通函数，不能被调用

```cpp
Point p;
p.Point(1.0, 2.0);  // 编译错误：构造函数不能被直接调用
```

如果想重新设置值，应该提供一个普通的成员函数（比如 `setX()`）。

### ⚠️ 创建对象数组时，必须有默认构造函数

```cpp
class Widget {
public:
    int id;
    explicit Widget(int n) : id(n) {}
    // 没有默认构造函数！
};

Widget arr[5];   // 编译错误：需要默认构造函数来初始化每个元素
```

### ⚠️ 注意 `Point p()` 的陷阱

```cpp
Point p();   // ⚠️ 这不是创建对象！这是声明一个返回 Point 的函数！

Point p;     // 正确：创建一个 Point 对象，调用默认构造函数
Point p{};   // C++11 也正确，统一初始化语法
```

这是 C++ 著名的"most vexing parse"问题，初学者经常踩坑。

## 八、完整示例：时间类

综合运用初始化列表、重载、`explicit`、委托构造：

```cpp
// Time.h
#pragma once

class Time {
public:
    const int SECONDS_PER_DAY = 86400;  // const 成员，必须用初始化列表

    int hour;
    int minute;
    int second;

    Time();                                  // 00:00:00
    explicit Time(int totalSeconds);         // 从总秒数构造
    Time(int h, int m, int s);               // 直接指定时分秒

    int toSeconds() const;
    void print() const;
};
```

```cpp
// Time.cpp
#include "Time.h"
#include <iostream>
#include <iomanip>

Time::Time() : SECONDS_PER_DAY(86400), hour(0), minute(0), second(0) {}

Time::Time(int totalSeconds)
    : SECONDS_PER_DAY(86400),
      hour(totalSeconds / 3600),
      minute((totalSeconds % 3600) / 60),
      second(totalSeconds % 60) {}

Time::Time(int h, int m, int s)
    : SECONDS_PER_DAY(86400), hour(h), minute(m), second(s) {}

int Time::toSeconds() const {
    return hour * 3600 + minute * 60 + second;
}

void Time::print() const {
    std::cout << std::setw(2) << std::setfill('0') << hour   << ":"
              << std::setw(2) << std::setfill('0') << minute << ":"
              << std::setw(2) << std::setfill('0') << second << std::endl;
}
```

```cpp
// main.cpp
#include "Time.h"

int main() {
    Time t1;              // 00:00:00
    Time t2(3661);        // 01:01:01（3661 秒）
    Time t3(14, 30, 0);   // 14:30:00

    t1.print();
    t2.print();
    t3.print();

    return 0;
}
```

**输出：**

```
00:00:00
01:01:01
14:30:00
```

## 九、本课小结

| 概念 | 要点 |
|---|---|
| 构造函数 | 与类同名，无返回值，对象创建时自动调用 |
| 默认构造函数 | 无参数；自己写了有参构造后编译器不再自动生成 |
| 构造函数重载 | 参数列表不同即可区分，编译器自动匹配 |
| 初始化列表 | 用 `:` 引导，在函数体执行前完成初始化；`const`、引用、无默认构造的成员**必须**用它 |
| 初始化顺序 | 按**成员声明顺序**，与列表书写顺序无关 |
| `explicit` | 禁止单参数构造函数的隐式类型转换，单参构造函数默认加它 |
| 委托构造 | 一个构造函数调用另一个，消除重复初始化逻辑 |

### 作业一：分数类（基础）

设计一个 `Fraction` 类表示分数（如 3/4），要求：

- 成员变量：分子 `numerator`（`int`）、分母 `denominator`（`int`）
- 提供以下构造函数：
  - 无参构造：默认初始化为 0/1
  - 单参构造（只传分子）：默认分母为 1，**用 `explicit` 修饰**
  - 双参构造：分别传分子和分母，分母为 0 时打印警告并将分母设置为 1
- 成员函数 `void print()`：输出格式为 `3/4`，若分母为 1 则只输出整数部分（如 `5`）
- 在 `main` 中测试各种构造方式，验证 `explicit` 是否确实阻止了隐式转换（故意写一个会报错的用法，注释掉，备注说明报错原因）

### 作业二：向量类 Vec3（进阶）

设计一个三维向量类 `Vec3`，要求：

- 三个成员变量：`double x, y, z`，**必须全部通过初始化列表初始化**，函数体内不得出现任何赋值
- 提供以下构造函数：
  - `Vec3()`：初始化为零向量 (0, 0, 0)，使用**委托构造**调用三参数版本
  - `Vec3(double all)`：三个分量相同，使用**委托构造**
  - `Vec3(double x, double y, double z)`：主构造函数，完成实际初始化
- 实现以下成员函数：
  - `double length()`：返回向量长度，需要 `#include <cmath>` 使用 `std::sqrt`
  - `Vec3 add(const Vec3& other)`：返回两向量相加的结果（返回一个新的 `Vec3` 对象）
  - `void print()`：输出格式为 `(1.00, 2.00, 3.00)`，保留两位小数
- 思考：`add` 函数返回新对象，这个新对象是如何被构造出来的？它会调用哪个构造函数？

### 作业三：配置项类（综合）

设计一个 `AppConfig` 类，模拟一个应用程序的启动配置，要求体现出本课"必须使用初始化列表"的三种情况：

- 成员变量：
  - `const std::string APP_NAME`（`const` 成员）
  - `const int MAX_CONNECTIONS`（`const` 成员）
  - `int& portRef`（引用成员，绑定到外部的一个 `int` 变量）
  - `std::string version`（普通字符串成员）
- 构造函数接受：应用名称、最大连接数、一个外部 `int` 变量的引用（作为端口号）、版本字符串
- **所有成员必须通过初始化列表完成初始化**，并在代码注释中标注为什么每个成员选择用初始化列表
- 实现 `void printConfig()`：打印所有配置项
- 在 `main` 中声明一个局部 `int port = 8080`，将其引用传入 `AppConfig`，构造完成后在 `main` 里修改 `port` 的值，再次调用 `printConfig()` 观察 `portRef` 是否跟着改变，并写注释解释原因
