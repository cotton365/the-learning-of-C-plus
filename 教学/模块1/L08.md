## 一、static 成员变量

### 1.1 问题从哪里来

先看一个普通成员变量做不到的事：统计当前创建了多少个对象。

```cpp
class Robot {
public:
    int count = 0;   // 想用它统计对象数量？

    Robot() {
        count++;     // 每次构造加 1
    }
};

Robot r1;
Robot r2;

// r1.count 是 1，r2.count 也是 1
// 它们各自有自己的 count，互不干扰——统计失败
```

每个对象都有自己独立的成员变量，这正是封装的本意，但在这里反而是障碍。我们需要一个**被所有对象共享**的变量，让任何一个对象修改它，其他对象都能看到变化。

这就是 `static` 成员变量的用途。

### 1.2 static 成员变量的本质

`static` 成员变量**属于类本身，而不属于任何一个对象**。无论创建了多少个对象，内存中只有这个变量的一份拷贝。

```cpp
class Robot {
public:
    static int count;   // 声明：所有 Robot 对象共享这一个 count

    std::string name;

    Robot(std::string n) : name(n) {
        count++;
    }

    ~Robot() {
        count--;
    }
};

// 定义（必须在类外写，这是 static 成员变量的语法要求）
int Robot::count = 0;

int main() {
    Robot r1("R1");
    Robot r2("R2");

    std::cout << Robot::count << std::endl;   // 输出：2（推荐用类名访问）
    std::cout << r1.count    << std::endl;    // 输出：2（也能用对象访问，但不推荐）

    {
        Robot r3("R3");
        std::cout << Robot::count << std::endl;  // 输出：3
    }
    // r3 超出作用域，析构函数调用，count--

    std::cout << Robot::count << std::endl;  // 输出：2
}
```

### 1.3 类外定义：为什么必须写，怎么写

**这是初学者最容易踩的坑。**

`static` 成员变量在类内只是**声明**，告诉编译器"有这么个东西"。真正分配内存、确定初始值，必须在类外单独**定义**一次：

```cpp
// ✅ 正确：在 .cpp 文件中类外定义
int Robot::count = 0;

// ❌ 错误：只有类内声明，没有类外定义
// 链接时会报"未定义符号"错误（undefined reference）
```

**写在哪里？**

- 写在对应的 `.cpp` 文件中，不要写在 `.h` 头文件里
- 头文件会被多个 `.cpp` 包含，写在头文件里会导致重复定义

**唯一的例外**：`static const int`（整型常量）可以在类内直接初始化：

```cpp
class Config {
public:
    static const int MAX_PLAYERS = 4;    // 允许：整型常量
    static const double PI = 3.14159;    // ❌ 不允许：非整型需要类外定义
};
```

C++17 引入了 `inline static`，允许在类内直接定义非常量 static 成员，但不是所有编译环境都默认开启 C++17，建议先掌握传统写法。

## 二、static 成员函数

### 2.1 基本用法

`static` 成员函数同样属于类而不属于对象，因此：

- 可以通过类名直接调用，无需创建对象
- 内部**没有 `this` 指针**（因为它不依附于任何对象）
- 只能访问 `static` 成员变量和其他 `static` 成员函数

```cpp
class Robot {
public:
    static int count;
    std::string name;

    Robot(std::string n) : name(n) { count++; }

    static int getCount() {
        return count;           // ✅ 可以访问 static 成员
        // return name;         // ❌ 编译错误：没有 this，无法访问普通成员
    }
};

int Robot::count = 0;

int main() {
    std::cout << Robot::getCount() << std::endl;  // 0，不用创建对象就能调用

    Robot r1("R1"), r2("R2");
    std::cout << Robot::getCount() << std::endl;  // 2
}
```

### 2.2 适用场景

static 成员函数有两个典型用途：

**① 工具函数（不依赖对象状态）**

```cpp
class MathUtils {
public:
    static double clamp(double val, double lo, double hi) {
        if (val < lo) return lo;
        if (val > hi) return hi;
        return val;
    }

    static bool isPrime(int n) {
        if (n < 2) return false;
        for (int i = 2; i * i <= n; i++)
            if (n % i == 0) return false;
        return true;
    }
};

// 不用创建 MathUtils 对象，直接用
double x = MathUtils::clamp(1.5, 0.0, 1.0);   // 1.0
bool b  = MathUtils::isPrime(17);               // true
```

**② 单例模式（Singleton）的入口**

这是工程中使用 `static` 成员函数最著名的场景——保证全局只有一个实例：

```cpp
class Logger {
public:
    static Logger& getInstance() {
        static Logger instance;   // 第一次调用时构造，之后复用同一个
        return instance;
    }

    void log(const std::string& msg) {
        std::cout << "[LOG] " << msg << std::endl;
    }

private:
    Logger() {}   // 构造函数私有，外部无法 new 一个 Logger
};

int main() {
    Logger::getInstance().log("程序启动");
    Logger::getInstance().log("执行某操作");
    // 两次调用拿到的是同一个对象
}
```

> 单例模式在这里只是帮助理解 `static` 的一个展示——它有自己的优缺点和适用范围，在架构设计课题里会深入讨论。

## 三、友元函数（friend function）

### 3.1 为什么需要友元

封装的核心思想是：私有成员只有类自己能访问。但有时候，有些函数在设计上确实需要访问私有数据，又不适合成为成员函数。

最典型的例子是**重载 `<<` 运算符**：

```cpp
class Vector2D {
public:
    double x, y;
};

// 我们希望这样用：
Vector2D v = {3.0, 4.0};
std::cout << v;   // 输出 (3, 4)
```

`operator<<` 的左操作数是 `std::ostream`（即 `cout`），所以它不能是 `Vector2D` 的成员函数（成员函数的左操作数是 `Vector2D` 自身）。它必须是一个全局函数：

```cpp
std::ostream& operator<<(std::ostream& os, const Vector2D& v) {
    os << "(" << v.x << ", " << v.y << ")";
    return os;
}
```

如果 `x` 和 `y` 是 `public` 的，这没问题。但如果它们是 `private` 的，这个全局函数就无法访问它们。友元机制解决了这个矛盾。

### 3.2 友元函数的声明与使用

在类内用 `friend` 关键字声明某个函数为"朋友"，它就能访问该类的所有私有成员：

```cpp
class Vector2D {
private:
    double x, y;   // 现在是私有的

public:
    Vector2D(double x, double y) : x(x), y(y) {}

    // 声明友元函数——它不是成员函数，没有 this
    friend std::ostream& operator<<(std::ostream& os, const Vector2D& v);
    friend double dot(const Vector2D& a, const Vector2D& b);
};

// 在类外定义（注意：不需要再写 friend 关键字）
std::ostream& operator<<(std::ostream& os, const Vector2D& v) {
    os << "(" << v.x << ", " << v.y << ")";   // 能访问 private 成员
    return os;
}

double dot(const Vector2D& a, const Vector2D& b) {
    return a.x * b.x + a.y * b.y;            // 能访问 private 成员
}

int main() {
    Vector2D v1(1.0, 2.0);
    Vector2D v2(3.0, 4.0);

    std::cout << v1 << std::endl;              // (1, 2)
    std::cout << dot(v1, v2) << std::endl;     // 11
}
```

**友元函数的几个关键性质：**

| 性质 | 说明 |
|---|---|
| 不是成员函数 | 没有 `this` 指针，不通过对象调用 |
| 声明位置 | 在类内声明（`friend` 关键字），在类外定义 |
| 访问权限 | 可以访问声明它的类的所有私有/保护成员 |
| 不可继承 | 友元关系不会被子类继承 |
| 不可传递 | A 是 B 的友元，B 是 C 的友元，A 不是 C 的友元 |

### 3.3 友元函数与 operator<< 的固定写法

`operator<<` 是友元函数最常见的应用，它的写法基本是固定格式，值得单独记住：

```cpp
class Fraction {
private:
    int numerator;    // 分子
    int denominator;  // 分母

public:
    Fraction(int n, int d) : numerator(n), denominator(d) {}

    // 固定写法：返回 ostream 引用，第一个参数 ostream 引用，第二个 const 对象引用
    friend std::ostream& operator<<(std::ostream& os, const Fraction& f) {
        os << f.numerator << "/" << f.denominator;
        return os;   // 必须返回 os，才能支持链式调用 cout << a << b
    }
};

int main() {
    Fraction f(3, 4);
    std::cout << "分数是：" << f << std::endl;   // 分数是：3/4
}
```

> 注意 `return os;`——如果不返回，`cout << a << b` 这样的链式调用就会失败，因为链式调用依赖于上一次调用返回的 `ostream` 引用。

## 四、友元类（friend class）

### 4.1 基本用法

不只是函数，整个类也可以成为另一个类的友元。友元类中的**所有成员函数**都能访问被友元类的私有成员。

```cpp
class Engine {
private:
    int horsepower;
    bool isRunning;

public:
    Engine(int hp) : horsepower(hp), isRunning(false) {}

    // 声明 Car 类为 Engine 的友元
    friend class Car;
};

class Car {
private:
    Engine engine;
    std::string model;

public:
    Car(std::string m, int hp) : model(m), engine(hp) {}

    void start() {
        engine.isRunning = true;       // ✅ Car 可以访问 Engine 的私有成员
        std::cout << model << " 发动（" << engine.horsepower << " 马力）" << std::endl;
    }

    void stop() {
        engine.isRunning = false;
        std::cout << model << " 熄火" << std::endl;
    }
};

int main() {
    Car car("Tesla", 450);
    car.start();   // Tesla 发动（450 马力）
    car.stop();
}
```

### 4.2 友元类的使用原则

友元类授予的权限非常大（整个类的所有方法都能访问私有成员），因此要谨慎使用。

**适合用友元类的场景：**

- 两个类在设计上紧密耦合，不可分割——比如容器类（`List`）和它的迭代器（`ListIterator`）：迭代器需要直接操作链表的内部节点指针
- 测试类需要检查被测类的内部状态

**不适合用友元类的场景：**

- 只是为了少写几个 getter 函数——这是懒惰，不是设计
- 两个类之间并不存在逻辑上的紧密关系

## 五、深入理解：友元破坏封装了吗

这是一个值得认真思考的问题。

表面上看，友元函数/类能访问私有成员，似乎破坏了封装。但实际上：

- **友元关系是类主动授予的**。`friend` 声明写在类的内部，由类的作者来决定谁是朋友。外部代码无法强行成为某个类的友元。
- **封装的本质是隐藏实现细节，控制访问权限**。友元机制是类在设计时主动选择"我信任这个函数/类可以看到我的内部"，这是一种有意为之的设计决策，不是漏洞。

真正破坏封装的是：滥用友元，把本来应该通过接口交互的逻辑，都改成直接访问私有数据。

**判断依据：**

> 如果去掉这个友元，设计会变得非常扭曲或低效，那么友元的使用可能是合理的。如果去掉友元只是让你多写两个 getter，那友元就是偷懒，应该去掉。

## 六、注意事项汇总

### ⚠️ static 成员变量忘记类外定义是最高频错误

```cpp
// A.h
class A {
public:
    static int count;
};

// 如果没有这一行（通常在 A.cpp 里），链接时报错：
// undefined reference to `A::count`
int A::count = 0;
```

### ⚠️ static 成员函数不能访问非 static 成员

```cpp
class Foo {
    int x = 0;
    static int y;

    static void bar() {
        y++;       // ✅ 可以
        x++;       // ❌ 编译错误：没有 this，x 属于哪个对象？
    }
};
```

### ⚠️ static 成员变量不在构造函数的初始化列表里初始化

```cpp
class Foo {
    static int count;
    Foo() : count(0) {}   // ❌ 错误！static 成员不通过初始化列表
};

int Foo::count = 0;       // ✅ 正确：类外定义时赋初值
```

### ⚠️ 友元函数定义时不加 friend 关键字

```cpp
class Box {
    friend void print(const Box& b);   // 类内声明，有 friend
};

// 类外定义，不再写 friend
void print(const Box& b) {             // ✅
    // ...
}

friend void print(const Box& b) {     // ❌ 错误
    // friend 只用于类内声明
}
```

### ⚠️ 友元关系单向且不可传递

```cpp
class B;
class A {
    friend class B;   // B 是 A 的友元：B 可以访问 A 的私有成员
                      // 但 A 不能访问 B 的私有成员（不是双向的）
};
```

## 七、完整综合示例：计数器 + 可打印的矩形

```cpp
#pragma once
#include <iostream>
#include <string>

class Rectangle {
private:
    double width;
    double height;
    static int instanceCount;   // 记录当前存活的 Rectangle 数量

public:
    Rectangle(double w, double h) : width(w), height(h) {
        instanceCount++;
    }

    ~Rectangle() {
        instanceCount--;
    }

    double area() const {
        return width * height;
    }

    static int getCount() {
        return instanceCount;
    }

    // 友元：让 operator<< 访问私有成员
    friend std::ostream& operator<<(std::ostream& os, const Rectangle& r);

    // 友元函数：比较两个矩形面积
    friend bool largerThan(const Rectangle& a, const Rectangle& b);
};

int Rectangle::instanceCount = 0;

std::ostream& operator<<(std::ostream& os, const Rectangle& r) {
    os << "Rectangle(" << r.width << " x " << r.height
       << ", area=" << r.area() << ")";
    return os;
}

bool largerThan(const Rectangle& a, const Rectangle& b) {
    return a.area() > b.area();
}
```

```cpp
#include "Rectangle.h"

int main() {
    std::cout << "存活数量：" << Rectangle::getCount() << std::endl;  // 0

    Rectangle r1(3.0, 4.0);
    Rectangle r2(5.0, 6.0);

    std::cout << r1 << std::endl;                               // Rectangle(3 x 4, area=12)
    std::cout << r2 << std::endl;                               // Rectangle(5 x 6, area=30)
    std::cout << "存活数量：" << Rectangle::getCount() << std::endl;  // 2

    if (largerThan(r2, r1))
        std::cout << "r2 更大" << std::endl;

    {
        Rectangle r3(1.0, 1.0);
        std::cout << "存活数量：" << Rectangle::getCount() << std::endl;  // 3
    }

    std::cout << "存活数量：" << Rectangle::getCount() << std::endl;  // 2
    return 0;
}
```

## 八、本课小结

| 概念 | 核心要点 |
|---|---|
| `static` 成员变量 | 属于类，所有对象共享一份；声明在类内，**定义必须在类外** |
| `static` 成员函数 | 没有 `this`，只能访问 `static` 成员；可用类名直接调用 |
| 友元函数 | 类内 `friend` 声明，类外定义；不是成员函数，无 `this` |
| 友元类 | 整个类的所有方法都能访问目标类的私有成员；谨慎使用 |
| `operator<<` | 必须是友元函数（左操作数是 ostream）；记住返回 `os` 引用 |
| 友元的本质 | 类**主动授权**，不是破坏封装——但要避免滥用 |

### 作业一：对象计数器（考查 static 成员变量 + 成员函数）

设计一个 `Session` 类，模拟网络会话管理：

- 用 `static` 成员变量记录当前活跃的会话总数（`activeCount`）和历史创建的总数（`totalCreated`）
- 每次构造一个 `Session` 对象，`activeCount` 和 `totalCreated` 各加 1
- 每次销毁一个 `Session` 对象，`activeCount` 减 1（`totalCreated` 不减，它记录历史）
- 提供 `static` 成员函数 `printStats()`，打印当前活跃数和历史总数
- 每个 `Session` 有一个 `id`（整数），可以在构造时传入

在 `main` 中模拟这样的场景：创建若干会话，让部分会话在局部作用域中被销毁，在不同时间点调用 `printStats()` 观察数字变化。

### 作业二：可比较、可打印的分数类（考查友元函数 + operator 重载）

设计一个 `Fraction`（分数）类：

- 私有成员：分子 `numerator`、分母 `denominator`
- 构造时需要确保分母不为 0（分母为 0 时打印错误并设为默认值 1）
- 实现以下友元函数（**全部以友元形式实现**，不得改为 public 成员函数）：
  - `operator<<`：以 `3/4` 格式输出；如果分母为 1，只输出整数部分（如 `5`）
  - `operator==`：判断两个分数是否相等（注意：`1/2` 和 `2/4` 是相等的，需要化简或交叉相乘比较）
  - `operator+`：两个分数相加，返回一个新的 `Fraction`（不需要化简结果，但要保证分母不为 0）
- 在 `main` 中验证：创建几个分数，打印它们，测试加法和相等比较

**提示**：`a/b == c/d` 等价于 `a * d == b * c`，这样可以避免浮点误差。

  - 新 x = v.x * scaleX + translateX
