## 一、问题场景:为什么需要虚析构函数

### 1.1 多态删除的陷阱

假设你在开发一个图形系统,使用基类指针管理不同类型的图形对象:

```cpp
#include <iostream>

class Shape {
public:
    Shape() {
        std::cout << "Shape 构造" << std::endl;
    }
    
    ~Shape() {  // ⚠️ 非虚析构函数
        std::cout << "Shape 析构" << std::endl;
    }
};

class Circle : public Shape {
private:
    double* radius;  // 动态分配的资源
    
public:
    Circle(double r) {
        radius = new double(r);
        std::cout << "Circle 构造, radius = " << *radius << std::endl;
    }
    
    ~Circle() {
        std::cout << "Circle 析构, 释放 radius" << std::endl;
        delete radius;  // 释放动态内存
    }
};

int main() {
    Shape* shape = new Circle(5.0);
    delete shape;  // ⚠️ 危险!
}
```

**输出:**
```
Shape 构造
Circle 构造, radius = 5
Shape 析构
```

**问题所在:**
- `Circle` 的析构函数**没有被调用**!
- `radius` 指向的内存**没有被释放** → 内存泄漏
- 只调用了 `Shape` 的析构函数

**原因:**当 `delete shape` 时,编译器看到 `shape` 是 `Shape*` 类型,就静态绑定到 `Shape::~Shape()`,不管它实际指向什么对象。

### 1.2 虚析构函数的解决方案

在基类析构函数前加 `virtual` 关键字:

```cpp
class Shape {
public:
    Shape() {
        std::cout << "Shape 构造" << std::endl;
    }
    
    virtual ~Shape() {  // ✅ 虚析构函数
        std::cout << "Shape 析构" << std::endl;
    }
};

class Circle : public Shape {
private:
    double* radius;
    
public:
    Circle(double r) {
        radius = new double(r);
        std::cout << "Circle 构造, radius = " << *radius << std::endl;
    }
    
    ~Circle() override {  // override 可选但推荐
        std::cout << "Circle 析构, 释放 radius" << std::endl;
        delete radius;
    }
};

int main() {
    Shape* shape = new Circle(5.0);
    delete shape;  // ✅ 安全
}
```

**输出:**
```
Shape 构造
Circle 构造, radius = 5
Circle 析构, 释放 radius
Shape 析构
```

完美!现在:
- `Circle` 的析构函数被正确调用
- `radius` 的内存被正确释放
- 然后自动调用 `Shape` 的析构函数

## 二、虚析构函数的原理

### 2.1 析构函数的调用链

普通继承中,析构函数的调用顺序是:**派生类析构 → 基类析构**(与构造顺序相反)。

加上 `virtual` 后,通过基类指针/引用删除派生类对象时:
1. 查找 vtable,找到派生类的析构函数
2. 调用派生类析构函数
3. 派生类析构完成后,自动调用基类析构函数
4. 这个过程递归进行,直到最顶层基类

### 2.2 虚析构函数与 vtable

虚析构函数也是虚函数,在 vtable 中占据一个位置:

```
Shape 的 vtable:
┌────────────────────┐
│ &Shape::~Shape     │
└────────────────────┘

Circle 的 vtable:
┌────────────────────┐
│ &Circle::~Circle   │  ← 覆盖了基类的析构
└────────────────────┘
```

当 `delete shape` 时:
1. 读取 `shape` 指向对象的 vptr
2. 从 vtable 中找到析构函数指针
3. 调用 `Circle::~Circle()`(而非 `Shape::~Shape()`)

### 2.3 完整示例:验证调用顺序

```cpp
#include <iostream>

class Base {
public:
    Base() { std::cout << "1. Base 构造" << std::endl; }
    virtual ~Base() { std::cout << "4. Base 析构" << std::endl; }
};

class Derived : public Base {
public:
    Derived() { std::cout << "2. Derived 构造" << std::endl; }
    ~Derived() override { std::cout << "3. Derived 析构" << std::endl; }
};

int main() {
    std::cout << "=== 直接用对象 ===" << std::endl;
    {
        Derived d;
    }
    
    std::cout << "\n=== 通过基类指针(有虚析构) ===" << std::endl;
    {
        Base* p = new Derived();
        delete p;
    }
}
```

**输出:**
```
=== 直接用对象 ===
1. Base 构造
2. Derived 构造
3. Derived 析构
4. Base 析构

=== 通过基类指针(有虚析构) ===
1. Base 构造
2. Derived 构造
3. Derived 析构
4. Base 析构
```

两种方式的析构顺序完全一致 → 虚析构函数确保了多态删除的安全性。

## 三、虚析构函数的使用规则

### 3.1 核心规则:基类析构函数要么是虚的,要么是 protected

**规则:**如果一个类会被用作基类,并且可能通过基类指针删除派生类对象,析构函数必须是虚的。

```cpp
// ✅ 正确:公有虚析构
class Base {
public:
    virtual ~Base() {}
};

// ✅ 也正确:受保护的非虚析构
class Base {
protected:
    ~Base() {}  // 外部不能通过基类指针删除
};
```

**为什么 `protected` 析构也可以?**

如果析构函数是 `protected`,外部代码无法通过基类指针 `delete`,只能通过派生类指针删除:

```cpp
class Base {
protected:
    ~Base() {}  // protected,不能被外部调用
};

class Derived : public Base {
public:
    ~Derived() {}  // public,可以被外部调用
};

int main() {
    Base* p = new Derived();
    delete p;  // ❌ 编译错误:Base::~Base() 是 protected
    
    Derived* pd = new Derived();
    delete pd;  // ✅ 可以
}
```

这种设计用于防止误用基类指针删除对象。

### 3.2 何时需要虚析构函数

**需要虚析构的场景:**
1. 类是多态基类(含有虚函数)
2. 可能通过基类指针删除派生类对象
3. 派生类有需要清理的资源(如动态内存、文件句柄等)

```cpp
// ✅ 需要虚析构
class Shape {
public:
    virtual void draw() = 0;  // 有虚函数 → 多态基类
    virtual ~Shape() {}       // 必须有虚析构
};
```

**不需要虚析构的场景:**
1. 不会被继承的类(可用 `final` 标记)
2. 不含虚函数的类(不用于多态)
3. 纯数据类(POD 类型)

```cpp
// ✅ 不需要虚析构
class Point {  // 纯数据类,不用于多态
public:
    double x, y;
    ~Point() {}  // 普通析构即可
};

class FinalClass final {  // 不能被继承
public:
    virtual void func() {}
    ~FinalClass() {}  // 不需要虚析构
};
```

### 3.3 标准库容器不适合作为公有基类

**重要提醒:**STL 容器(如 `std::vector`,`std::string`)的析构函数都**不是虚的**,因此不应该公有继承它们:

```cpp
// ❌ 错误的设计
class MyVector : public std::vector<int> {
public:
    ~MyVector() {
        // 清理资源...
    }
};

std::vector<int>* v = new MyVector();
delete v;  // ⚠️ 未定义行为!MyVector::~MyVector() 不会被调用
```

**正确做法:**用组合而非继承:

```cpp
// ✅ 正确的设计
class MyVector {
private:
    std::vector<int> data;  // 组合
public:
    // 提供需要的接口...
};
```

## 四、虚析构函数的性能开销

### 4.1 开销分析

虚析构函数带来的开销:
- **vtable 空间:**每个类的 vtable 多一个析构函数指针
- **vptr 空间:**每个对象多一个 vptr(8 字节,64 位系统)
- **间接调用:**析构时多一次虚函数表查找

**性能影响:**
- 对于大多数应用,开销可以忽略
- 对于性能敏感的场景(如嵌入式系统、高频对象创建),需要权衡

### 4.2 虚析构函数使对象不再是 POD

Plain Old Data(POD)类型是 C++ 中一种特殊的类型,可以用 C 的方式处理(如 `memcpy`)。

```cpp
struct PodStruct {
    int x;
    double y;
};
// sizeof(PodStruct) = 16 字节(考虑对齐)

struct NonPodStruct {
    int x;
    double y;
    virtual ~NonPodStruct() {}  // 虚析构
};
// sizeof(NonPodStruct) = 24 字节(多了 vptr)
// 不再是 POD,不能用 memcpy
```

**影响:**
- 虚析构函数使类失去 POD 特性
- 不能用 `memcpy`,`memset` 等 C 风格函数
- 不能用于某些底层优化场景

## 五、常见陷阱与注意事项

### ⚠️ 忘记在基类中声明虚析构

```cpp
class Base {
public:
    ~Base() {}  // ❌ 不是虚的
};

class Derived : public Base {
private:
    int* data;
public:
    Derived() { data = new int[100]; }
    ~Derived() { delete[] data; }
};

Base* p = new Derived();
delete p;  // ⚠️ 内存泄漏!Derived::~Derived() 未调用
```

**后果:**派生类的析构函数不被调用 → 资源泄漏、未定义行为。

### ⚠️ 派生类析构函数自动是虚的

如果基类析构是虚的,派生类析构**自动也是虚的**,即使不显式写 `virtual`:

```cpp
class Base {
public:
    virtual ~Base() {}
};

class Derived : public Base {
public:
    ~Derived() {}  // 自动是虚的(隐式 override)
};
```

**建议:**显式加上 `override` 关键字,增强代码可读性:

```cpp
class Derived : public Base {
public:
    ~Derived() override {}  // ✅ 更清晰
};
```

### ⚠️ 在构造/析构中调用虚函数的陷阱

在析构函数中调用虚函数,**不会触发多态**:

```cpp
class Base {
public:
    virtual ~Base() {
        cleanup();  // ⚠️ 调用的是 Base::cleanup()
    }
    
    virtual void cleanup() {
        std::cout << "Base cleanup" << std::endl;
    }
};

class Derived : public Base {
public:
    ~Derived() override {
        std::cout << "Derived 析构" << std::endl;
    }
    
    void cleanup() override {
        std::cout << "Derived cleanup" << std::endl;
    }
};

Derived d;  // 析构时输出 "Derived 析构" 然后 "Base cleanup"
```

**原因:**析构 `Derived` 时,先执行 `Derived::~Derived()`,然后进入 `Base::~Base()`。此时 `Derived` 部分已销毁,vptr 指向 `Base` 的 vtable,所以 `cleanup()` 调用的是 `Base::cleanup()`。

**建议:**避免在析构函数中调用虚函数,改为直接调用需要的函数。

### ⚠️ 虚析构函数可以是纯虚的

析构函数可以声明为纯虚,但**必须提供实现**:

```cpp
class AbstractBase {
public:
    virtual ~AbstractBase() = 0;  // 纯虚析构
};

// ⚠️ 必须提供实现!
AbstractBase::~AbstractBase() {
    std::cout << "AbstractBase 析构" << std::endl;
}
```

**原因:**派生类析构完成后,会自动调用基类析构。如果没有实现,链接时报错。

**用途:**让类成为抽象类,同时保证析构是虚的。实际中较少使用,通常用纯虚函数声明接口更清晰。

## 六、完整综合示例:资源管理类层次

```cpp
#include <iostream>
#include <string>
#include <vector>
#include <memory>

// ──────────────────────────────────
// 基类:资源(抽象类)
// ──────────────────────────────────
class Resource {
protected:
    std::string name;
    
public:
    Resource(const std::string& n) : name(n) {
        std::cout << "[Resource] 构造: " << name << std::endl;
    }
    
    // ⚠️ 关键:虚析构函数
    virtual ~Resource() {
        std::cout << "[Resource] 析构: " << name << std::endl;
    }
    
    // 纯虚函数:强制派生类实现
    virtual void use() = 0;
    virtual void release() = 0;
    
    std::string getName() const { return name; }
};

// ──────────────────────────────────
// 派生类1:文件资源
// ──────────────────────────────────
class FileResource : public Resource {
private:
    int* fileHandle;  // 模拟文件句柄
    
public:
    FileResource(const std::string& filename)
        : Resource(filename) {
        fileHandle = new int(123);  // 模拟打开文件
        std::cout << "[FileResource] 打开文件, 句柄: " << *fileHandle << std::endl;
    }
    
    ~FileResource() override {
        std::cout << "[FileResource] 关闭文件: " << name << std::endl;
        delete fileHandle;  // 释放资源
    }
    
    void use() override {
        std::cout << "[FileResource] 读写文件: " << name << std::endl;
    }
    
    void release() override {
        std::cout << "[FileResource] 释放文件锁: " << name << std::endl;
    }
};

// ──────────────────────────────────
// 派生类2:网络连接资源
// ──────────────────────────────────
class NetworkResource : public Resource {
private:
    char* buffer;  // 接收缓冲区
    int port;
    
public:
    NetworkResource(const std::string& host, int p)
        : Resource(host), port(p) {
        buffer = new char[1024];  // 分配缓冲区
        std::cout << "[NetworkResource] 连接到 " << host 
                  << ":" << port << std::endl;
    }
    
    ~NetworkResource() override {
        std::cout << "[NetworkResource] 断开连接: " << name << std::endl;
        delete[] buffer;  // 释放缓冲区
    }
    
    void use() override {
        std::cout << "[NetworkResource] 发送/接收数据: " 
                  << name << ":" << port << std::endl;
    }
    
    void release() override {
        std::cout << "[NetworkResource] 关闭套接字: " 
                  << name << std::endl;
    }
};

// ──────────────────────────────────
// 派生类3:数据库连接资源
// ──────────────────────────────────
class DatabaseResource : public Resource {
private:
    std::vector<std::string>* queryCache;  // 查询缓存
    
public:
    DatabaseResource(const std::string& dbName)
        : Resource(dbName) {
        queryCache = new std::vector<std::string>();
        std::cout << "[DatabaseResource] 连接数据库: " << dbName << std::endl;
    }
    
    ~DatabaseResource() override {
        std::cout << "[DatabaseResource] 关闭数据库: " << name << std::endl;
        delete queryCache;  // 清理缓存
    }
    
    void use() override {
        std::cout << "[DatabaseResource] 执行查询: " << name << std::endl;
        queryCache->push_back("SELECT * FROM users");
    }
    
    void release() override {
        std::cout << "[DatabaseResource] 提交事务: " << name << std::endl;
    }
};

// ──────────────────────────────────
// 资源管理器
// ──────────────────────────────────
class ResourceManager {
private:
    std::vector<Resource*> resources;
    
public:
    void addResource(Resource* res) {
        resources.push_back(res);
    }
    
    void useAllResources() {
        std::cout << "\n=== 使用所有资源 ===" << std::endl;
        for (auto res : resources) {
            res->use();
        }
    }
    
    void releaseAllResources() {
        std::cout << "\n=== 释放所有资源 ===" << std::endl;
        for (auto res : resources) {
            res->release();
        }
    }
    
    ~ResourceManager() {
        std::cout << "\n=== 清理资源管理器 ===" << std::endl;
        for (auto res : resources) {
            delete res;  // ✅ 虚析构确保正确释放
        }
        resources.clear();
    }
};

// ──────────────────────────────────
// 主程序
// ──────────────────────────────────
int main() {
    std::cout << "=== 创建资源 ===" << std::endl;
    ResourceManager manager;
    
    manager.addResource(new FileResource("config.txt"));
    manager.addResource(new NetworkResource("192.168.1.1", 8080));
    manager.addResource(new DatabaseResource("myapp_db"));
    
    manager.useAllResources();
    manager.releaseAllResources();
    
    std::cout << "\n=== main 结束,自动清理 ===" << std::endl;
    return 0;
}
```

**输出:**
```
=== 创建资源 ===
[Resource] 构造: config.txt
[FileResource] 打开文件, 句柄: 123
[Resource] 构造: 192.168.1.1
[NetworkResource] 连接到 192.168.1.1:8080
[Resource] 构造: myapp_db
[DatabaseResource] 连接数据库: myapp_db

=== 使用所有资源 ===
[FileResource] 读写文件: config.txt
[NetworkResource] 发送/接收数据: 192.168.1.1:8080
[DatabaseResource] 执行查询: myapp_db

=== 释放所有资源 ===
[FileResource] 释放文件锁: config.txt
[NetworkResource] 关闭套接字: 192.168.1.1
[DatabaseResource] 提交事务: myapp_db

=== main 结束,自动清理 ===

=== 清理资源管理器 ===
[FileResource] 关闭文件: config.txt
[Resource] 析构: config.txt
[NetworkResource] 断开连接: 192.168.1.1
[Resource] 析构: 192.168.1.1
[DatabaseResource] 关闭数据库: myapp_db
[Resource] 析构: myapp_db
```

**关键观察:**
- 每个派生类的析构函数都被正确调用
- 所有动态分配的资源都被正确释放
- 析构顺序:派生类 → 基类(自动进行)

## 七、本课小结

| 概念 | 核心要点 |
|---|---|
| 虚析构函数定义 | 基类析构函数声明为 `virtual ~Base() {}` |
| 解决的问题 | 通过基类指针删除派生类对象时,确保派生类析构被调用 |
| 调用顺序 | 派生类析构 → 基类析构(递归到顶层),与构造相反 |
| 何时需要 | 多态基类(含虚函数) + 可能通过基类指针删除 + 派生类有资源 |
| 何时不需要 | 不会被继承的类、不含虚函数的类、纯数据类 |
| 性能开销 | 每对象多 vptr(8 字节),析构多一次间接调用 |
| 常见陷阱 | 忘记虚析构 → 内存泄漏;STL 容器无虚析构,不应公有继承 |
| `override` | 派生类析构自动是虚的,建议显式加 `override` |

**核心口诀:**
- 多态基类必须有虚析构
- 虚析构确保资源正确释放
- STL 容器不可公有继承

## 八、实战作业

### 作业一:虚析构函数基础验证(考查虚析构语法 + 资源释放)

实现一个简单的图形类层次,验证虚析构函数的作用。

**第一步:不使用虚析构**

```cpp
class Shape {
public:
    Shape() { std::cout << "Shape 构造" << std::endl; }
    ~Shape() { std::cout << "Shape 析构" << std::endl; }  // 非虚
};

class Circle : public Shape {
private:
    double* radius;
public:
    Circle(double r) {
        radius = new double(r);
        std::cout << "Circle 构造, radius = " << *radius << std::endl;
    }
    ~Circle() {
        std::cout << "Circle 析构, 释放 radius" << std::endl;
        delete radius;
    }
};
```

要求:
1. 在 `main` 中创建 `Shape* s = new Circle(5.0);`
2. 使用 `delete s;` 删除对象
3. 观察并记录输出,分析是否有内存泄漏

**第二步:添加虚析构**

1. 将 `Shape` 的析构函数改为 `virtual ~Shape()`
2. 给 `Circle` 的析构函数加上 `override`
3. 再次运行,记录输出
4. 对比两次输出的区别

### 作业二:资源泄漏检测与修复(考查内存安全 + 析构顺序)

这道题需要你**识别和修复虚析构相关的内存泄漏**。

**背景:**以下是一个有 bug 的媒体播放器代码:

```cpp
#include <iostream>
#include <string>

class MediaPlayer {
protected:
    std::string filename;
public:
    MediaPlayer(const std::string& file) : filename(file) {
        std::cout << "打开媒体: " << filename << std::endl;
    }
    
    ~MediaPlayer() {  // ⚠️ 问题在这里
        std::cout << "关闭媒体: " << filename << std::endl;
    }
    
    virtual void play() = 0;
};

class AudioPlayer : public MediaPlayer {
private:
    int* audioBuffer;  // 音频缓冲区
    int bufferSize;
public:
    AudioPlayer(const std::string& file, int size)
        : MediaPlayer(file), bufferSize(size) {
        audioBuffer = new int[bufferSize];
        std::cout << "分配音频缓冲区: " << bufferSize << " 个 int" << std::endl;
    }
    
    ~AudioPlayer() {
        std::cout << "释放音频缓冲区" << std::endl;
        delete[] audioBuffer;
    }
    
    void play() override {
        std::cout << "播放音频: " << filename << std::endl;
    }
};

class VideoPlayer : public MediaPlayer {
private:
    char* videoFrame;  // 视频帧缓冲
    int frameSize;
public:
    VideoPlayer(const std::string& file, int size)
        : MediaPlayer(file), frameSize(size) {
        videoFrame = new char[frameSize];
        std::cout << "分配视频帧缓冲: " << frameSize << " 字节" << std::endl;
    }
    
    ~VideoPlayer() {
        std::cout << "释放视频帧缓冲" << std::endl;
        delete[] videoFrame;
    }
    
    void play() override {
        std::cout << "播放视频: " << filename << std::endl;
    }
};

void playMedia(MediaPlayer* player) {
    player->play();
    delete player;  // ⚠️ 这里会导致内存泄漏
}

int main() {
    playMedia(new AudioPlayer("song.mp3", 1024));
    playMedia(new VideoPlayer("movie.mp4", 2048));
}
```

**任务:**

1. **分析问题:**
   - 运行代码,记录输出
   - 识别哪些析构函数没有被调用
   - 计算总共泄漏了多少字节的内存

2. **修复问题:**
   - 修改代码,确保所有资源都被正确释放
   - 再次运行,验证所有析构函数都被调用

3. **验证析构顺序:**
   - 在每个类的析构函数中打印 "开始析构" 和 "结束析构"
   - 观察多层继承时的析构顺序
   - 如果有三层继承(`Media → Video → StreamingVideo`),析构顺序是什么?

**回答以下问题**(写在代码注释或单独文本中):
- 为什么基类指针删除派生类对象时,如果析构不是虚的,派生类析构不会被调用?
- 析构函数中调用虚函数会触发多态吗?为什么?
- 如果在 `VideoPlayer` 的析构中忘记 `delete[] videoFrame`,这个问题在编译期还是运行期暴露?如何检测?

### 作业三:智能指针与 RAII 资源管理(综合:虚析构 + RAII + 智能指针)

这道题是本课最综合的题目,需要你**设计一个资源管理系统**,体现 RAII 原则。

**背景:**

设计一个文件操作系统,支持不同类型的文件:
- 文本文件(`TextFile`):需要字符编码转换缓冲区
- 二进制文件(`BinaryFile`):需要读写缓冲区
- 压缩文件(`CompressedFile`):需要解压缩缓冲区

所有文件都需要在打开时分配资源,关闭时释放资源。

**需求:**

1. **定义抽象基类 `File`:**
   ```cpp
   class File {
   protected:
       std::string filename;
       bool isOpen;
   public:
       File(const std::string& name);
       virtual ~File();  // 虚析构
       
       virtual void open() = 0;   // 纯虚函数
       virtual void close() = 0;
       virtual void read() = 0;
       virtual void write(const std::string& data) = 0;
   };
   ```

2. **实现至少 3 个派生类:**
   - 每个派生类都包含动态分配的资源(如缓冲区)

   - 正确实现虚析构函数链

3. **使用智能指针管理文件对象:**
   ```cpp
   #include <memory>
   
   class FileManager {
   private:
       std::vector<std::unique_ptr<File>> files;  // 智能指针
   public:
       void addFile(std::unique_ptr<File> file);
       void openAll();
       void closeAll();
       // 析构时自动释放所有文件
   };
   ```

4. **在 `main` 中演示:**
   - 创建多个不同类型的文件对象
   - 将它们添加到 `FileManager`
   - 执行打开、读写、关闭操作
   - 让 `FileManager` 自动析构,观察所有资源是否正确释放

5. **对比裸指针和智能指针:**

   - 实现一个用智能指针的版本(`std::vector<std::unique_ptr<File>>`)
