## 一、多继承的基本语法

C++ 允许一个类同时继承多个基类：

```cpp
class Derived : public Base1, public Base2 {
    // ...
};
```

每个基类都可以独立指定继承方式（`public` / `protected` / `private`），逗号分隔。

**简单例子：**

```cpp
#include <iostream>
#include <string>

class Flyable {
public:
    void fly() { std::cout << "起飞！" << std::endl; }
};

class Swimmable {
public:
    void swim() { std::cout << "游泳！" << std::endl; }
};

// Duck 既能飞，又能游
class Duck : public Flyable, public Swimmable {
public:
    std::string name;
    Duck(std::string n) : name(n) {}
    void quack() { std::cout << name << "：嘎嘎！" << std::endl; }
};

int main() {
    Duck d("唐老鸭");
    d.fly();    // 来自 Flyable
    d.swim();   // 来自 Swimmable
    d.quack();  // Duck 自己的
}
```

**输出：**
```
起飞！
游泳！
唐老鸭：嘎嘎！
```

多继承在接口混入（Mixin）场景非常自然。上面两个基类没有任何共同成员，所以这个例子工作得很好。麻烦从两个基类有**同名成员**时开始。

## 二、二义性（Ambiguity）

### 2.1 什么是二义性

当两个基类都有同名的成员（函数或变量），派生类在不加限定地访问该成员时，编译器无法判断你要的是哪一个，于是报错——这就是**二义性**。

```cpp
class A {
public:
    void hello() { std::cout << "A::hello" << std::endl; }
};

class B {
public:
    void hello() { std::cout << "B::hello" << std::endl; }
};

class C : public A, public B {
    // 继承了两个 hello()
};

int main() {
    C c;
    c.hello();       // ❌ 编译错误：ambiguous call to 'hello'
}
```

注意：**二义性在编译期就报错**，不是运行时问题。即使两个 `hello()` 的实现完全相同，编译器也会拒绝，因为它没法推断你的意图。

### 2.2 用作用域解析运算符消除二义性

**解决方法**：用 `基类名::成员` 明确指定来源。

```cpp
int main() {
    C c;
    c.A::hello();    // ✅ 明确调用 A 的 hello
    c.B::hello();    // ✅ 明确调用 B 的 hello
}
```

在派生类内部也一样：

```cpp
class C : public A, public B {
public:
    void greet() {
        A::hello();   // ✅
        B::hello();   // ✅
    }
};
```

### 2.3 在派生类中覆盖同名函数

更常见的做法是在 `C` 中直接定义自己的 `hello()`，从而屏蔽两个父类的版本：

```cpp
class C : public A, public B {
public:
    void hello() {   // 覆盖，消除外部调用时的二义性
        A::hello();  // 可以在内部选择性复用
        std::cout << "C::hello（额外逻辑）" << std::endl;
    }
};

int main() {
    C c;
    c.hello();   // ✅ 调用 C 自己的 hello
}
```

## 三、菱形继承问题（重点 ⚠️）

### 3.1 菱形继承是什么

菱形继承（Diamond Inheritance）是指：**两个派生类都继承自同一个基类，然后一个更下层的类同时继承这两个派生类。**

```
     Animal
    /      \
  Dog      Cat
    \      /
     Hybrid
```

用代码写出来：

```cpp
class Animal {
public:
    std::string name;
    int hp;

    Animal(std::string n, int h) : name(n), hp(h) {}

    void breathe() {
        std::cout << name << " 在呼吸" << std::endl;
    }
};

class Dog : public Animal {
public:
    Dog(std::string n, int h) : Animal(n, h) {}
    void bark() { std::cout << "汪汪！" << std::endl; }
};

class Cat : public Animal {
public:
    Cat(std::string n, int h) : Animal(n, h) {}
    void meow() { std::cout << "喵喵！" << std::endl; }
};

class Hybrid : public Dog, public Cat {
public:
    Hybrid(std::string n, int h)
        : Dog(n, h), Cat(n, h) {}  // 两个基类都构造了一个 Animal！
};
```

### 3.2 问题的根本原因：两份 Animal 子对象

这是本课最核心的知识点，必须真正理解。

当 `Hybrid` 继承 `Dog` 和 `Cat` 时，它的**内存布局**如下：

```
Hybrid 对象的内存
┌─────────────────────────────────┐
│  Dog 子对象                      │
│  ┌──────────────────────────┐   │
│  │  Animal 子对象（第一份）   │   │
│  │  name, hp                │   │
│  └──────────────────────────┘   │
│  bark()                          │
├─────────────────────────────────┤
│  Cat 子对象                      │
│  ┌──────────────────────────┐   │
│  │  Animal 子对象（第二份）   │   │
│  │  name, hp                │   │
│  └──────────────────────────┘   │
│  meow()                          │
└─────────────────────────────────┘
```

`Hybrid` 对象里有**两份** `name` 和 `hp`，来自两条不同的继承路径。

这带来三个问题：

**① 内存浪费**：同一份逻辑数据存了两次。

**② 数据不一致风险**：如果通过 `Dog` 路径修改 `name`，`Cat` 路径的 `name` 不会跟着变——它们是两个独立的变量。

**③ 访问二义性**：直接访问 `name` 或调用 `breathe()` 时，编译器不知道你要哪一份：

```cpp
int main() {
    Hybrid h("混血", 100);

    h.bark();        // ✅ Dog 特有，无歧义
    h.meow();        // ✅ Cat 特有，无歧义

    h.breathe();     // ❌ 编译错误：二义性！有两个 breathe()
    h.name = "新名"; // ❌ 编译错误：二义性！有两个 name
}
```

### 3.3 用作用域解析"绕开"问题（治标）

和普通二义性一样，可以用作用域限定符强制选择：

```cpp
int main() {
    Hybrid h("混血", 100);

    h.Dog::breathe();    // ✅ 通过 Dog 路径的 Animal 调用
    h.Cat::breathe();    // ✅ 通过 Cat 路径的 Animal 调用

    h.Dog::name = "狗名";
    h.Cat::name = "猫名";

    std::cout << h.Dog::name << std::endl;  // 狗名
    std::cout << h.Cat::name << std::endl;  // 猫名（两份不同！）
}
```

这能**消除编译错误**，但**没有解决根本问题**——`Animal` 依然存在两份，数据依然不一致。

### 3.4 根本解决方案：虚继承（预告）

菱形继承问题的根本解决方案是**虚继承**（`virtual` 继承）：

```cpp
class Dog : public virtual Animal { ... };
class Cat : public virtual Animal { ... };
class Hybrid : public Dog, public Cat { ... };
// 现在 Hybrid 里只有一份 Animal 子对象
```

加上 `virtual` 关键字后，C++ 保证无论经过多少条路径，公共基类只会有**一份**子对象。

**本课先建立对问题的清晰认识。虚继承的语法细节、内存原理和构造规则在 L11 中专门深讲。**

## 四、何时使用多继承

多继承本身不是坏东西，滥用才是问题所在。以下是实际工程中的判断原则：

### ✅ 适合多继承的场景：接口混入（Mixin）

当多个基类都是**只含接口（纯虚函数）的抽象类**，不含数据成员时，多继承是安全且自然的：

```cpp
class Serializable {
public:
    virtual std::string serialize() const = 0;
    virtual void deserialize(const std::string&) = 0;
};

class Printable {
public:
    virtual void print() const = 0;
};

class Document : public Serializable, public Printable {
public:
    std::string serialize() const override { /* ... */ return ""; }
    void deserialize(const std::string&) override { /* ... */ }
    void print() const override { /* ... */ }
};
```

因为 `Serializable` 和 `Printable` 没有任何数据成员，也没有共同基类，所以不会有二义性，更不会出现菱形问题。这是多继承最常见的正当用法。

### ❌ 警惕的场景：多个含数据的实体类多继承

如果多个基类都有数据成员，并且存在共同的祖先类，就要非常谨慎——菱形继承的坑已经在等你了。遇到这种情况，先考虑是否可以用组合替代。

**一个简单的判断方法：**
- 多个基类都是"接口"（只有函数，没有状态）→ 多继承通常可以
- 多个基类都有"状态"（有成员变量）→ 考虑组合，或者仔细检查是否会出现共同祖先

## 五、注意事项

### ⚠️ 二义性在编译期报错，不是运行时问题

无论两个同名函数的实现是否相同，只要调用不加限定，就是编译错误。不要寄希望于"反正两个实现一样，编译器应该能猜到"。

### ⚠️ 菱形继承中，两份子对象的数据是相互独立的

```cpp
Hybrid h("混血", 100);
h.Dog::name = "通过Dog改的名字";
// h.Cat::name 依然是 "混血"，没有跟着变！
```

这种数据分裂极易导致逻辑 bug，是菱形继承最危险的地方。

### ⚠️ 构造顺序与初始化列表

多继承时，基类的构造顺序由**声明顺序**决定，而非初始化列表的书写顺序：

```cpp
class Hybrid : public Dog, public Cat {
public:
    Hybrid(std::string n, int h)
        : Cat(n, h), Dog(n, h)  // 写的是 Cat 先，但实际上 Dog 先构造！
    {}
};
// 构造顺序：Dog → Cat（按 class Hybrid : public Dog, public Cat 的顺序）
```

建议：**初始化列表的书写顺序与类定义中的继承顺序保持一致**，避免混淆。

### ⚠️ 析构顺序与构造顺序严格相反

多继承的析构顺序同样遵循"与构造相反"的原则：

```
构造：Dog → Cat → Hybrid 自己
析构：Hybrid 自己 → Cat → Dog
```

### ⚠️ 不要为了"代码复用"而强行使用多继承

如果两个类没有真正的"is-a"关系，却为了复用某个函数而把它作为基类继承，这是设计错误。用组合（has-a）或者自由函数来实现复用。

## 六、完整综合示例：水陆两用载具

```cpp
#include <iostream>
#include <string>

// ──────────────────────────────────
// 两个独立的能力接口（无数据成员，无共同基类）
// ──────────────────────────────────

class LandVehicle {
public:
    std::string brand;
    int speed;

    LandVehicle(std::string b, int s) : brand(b), speed(s) {}

    void drive() {
        std::cout << brand << " 在陆地行驶，速度 " << speed << " km/h" << std::endl;
    }
};

class WaterVehicle {
public:
    std::string brand;
    int waterSpeed;

    WaterVehicle(std::string b, int ws) : brand(b), waterSpeed(ws) {}

    void sail() {
        std::cout << brand << " 在水上航行，速度 " << waterSpeed << " 节" << std::endl;
    }
};

// ──────────────────────────────────
// AmphibiousVehicle 同时继承两者
// 注意：两个基类都有 brand，存在二义性
// ──────────────────────────────────

class AmphibiousVehicle : public LandVehicle, public WaterVehicle {
public:
    std::string model;

    AmphibiousVehicle(std::string brand, int landSpeed, int ws, std::string m)
        : LandVehicle(brand, landSpeed),
          WaterVehicle(brand, ws),
          model(m) {}

    void describe() {
        // brand 有二义性，必须加限定
        std::cout << "水陆两用：" << LandVehicle::brand
                  << " · " << model << std::endl;
        drive();
        sail();
    }

    // 在派生类中统一 brand，消除外部调用的二义性
    std::string getBrand() const {
        return LandVehicle::brand;  // 明确取哪一份
    }
};

int main() {
    AmphibiousVehicle av("DUKW", 80, 10, "二战水陆两用车");
    av.describe();
    std::cout << "品牌：" << av.getBrand() << std::endl;

    // 演示两份 brand 独立存在
    av.LandVehicle::brand = "陆地品牌";
    av.WaterVehicle::brand = "水上品牌";
    std::cout << "陆地品牌：" << av.LandVehicle::brand << std::endl;
    std::cout << "水上品牌：" << av.WaterVehicle::brand << std::endl;
}
```

**输出：**
```
水陆两用：DUKW · 二战水陆两用车
DUKW 在陆地行驶，速度 80 km/h
DUKW 在水上航行，速度 10 节
品牌：DUKW
陆地品牌：陆地品牌
水上品牌：水上品牌
```

最后两行清楚地显示：两份 `brand` 是完全独立的变量，修改其中一份不影响另一份。

## 七、本课小结

| 概念 | 核心要点 |
|---|---|
| 多继承语法 | `class C : public A, public B`，各基类独立指定继承方式 |
| 二义性 | 两个基类有同名成员时，不加限定的访问会编译报错 |
| 消除二义性 | 用 `Base::member` 作用域限定，或在派生类中覆盖同名成员 |
| 菱形继承根因 | 公共祖先基类的子对象在最终派生类中存在**两份**，数据独立、互不同步 |
| 作用域限定的局限 | 能消除编译错误，但无法消除"两份数据"本身的问题 |
| 根本解决方案 | 虚继承（`virtual Base`），详见 L11 |
| 适合多继承的场景 | 多个**纯接口基类**（无数据成员）的混入，安全且自然 |
| 构造顺序 | 按**类定义中的继承顺序**构造，不是初始化列表的书写顺序 |

### 作业一：多继承接口混入（考查多继承语法 + 作用域解析）

### 作业二：菱形继承问题复现与分析（考查菱形继承的根因理解）

**第一步：构建菱形继承结构**

```
      Device（设备基类）
      /             \

      \             /
       SmartDevice
```

- `Device`：成员变量 `std::string serialNumber`（序列号）和 `int powerConsumption`（功耗），提供构造函数和 `void printInfo()` 打印两者

- `SmartDevice`：同时继承 `NetworkDevice` 和 `StorageDevice`，新增 `std::string os`（操作系统）
